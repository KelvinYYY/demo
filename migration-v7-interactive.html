IntDef Annotations
2.17 Mechanical ~60 sites
@Target(TYPE_USE) was added to IntDef annotations in 2.17. Kotlin code using these as parameter-position type annotations may encounter compile warnings. In Media3 the annotations are already correctly scoped — this resolves itself after migration.
ExoPlayer 2.17 (warning)
// Kotlin annotation site @C.ContentType val type: Int
Media3 (resolved)
// Works as-is — annotations // updated to correct targets val type: @C.ContentType Int

Constructor → Builder Pattern
2.17–2.19 Adaptation ~15 files
Multi-argument constructors were removed across several core classes in favor of the Builder pattern. Each class now exposes a typed builder with explicit setter methods, improving discoverability and future extensibility.
1
DefaultRenderersFactory(context, decoderExtensionMode) → DefaultRenderersFactory(context).setExtensionRendererMode(mode)
2
DefaultTrackSelector(context, adaptiveFactory) → DefaultTrackSelector(context) — factory configured via Parameters
3
DefaultAudioSink(capabilities, processors) → DefaultAudioSink.Builder(context).setAudioProcessors(processors).build()
4
DefaultBandwidthMeter(context) → DefaultBandwidthMeter.Builder(context).build()
5
SimpleCache(dir, evictor) → SimpleCache(dir, evictor, StandaloneDatabaseProvider(context)) — DB provider now required
Before
val factory = DefaultRenderersFactory(context, EXTENSION_RENDERER_MODE_ON) val trackSelector = DefaultTrackSelector(context, AdaptiveTrackSelection.Factory()) val audioSink = DefaultAudioSink(capabilities, arrayOf(processor))
After
val factory = DefaultRenderersFactory(context) .setExtensionRendererMode(EXTENSION_RENDERER_MODE_ON) val trackSelector = DefaultTrackSelector(context) val audioSink = DefaultAudioSink.Builder(context) .setAudioProcessors(arrayOf(processor)) .build()

Format API → Builder
2.19 Adaptation ~30 files
All Format.create*() static factory methods and Format.copyWith*() mutation helpers were removed. Use Format.Builder for construction and format.buildUpon() for derived formats.
Before
val format = Format.createVideoSampleFormat( id, mimeType, null, bitrate, /*…*/) val newFormat = format .copyWithMaxInputSize(maxSize)
After
val format = Format.Builder() .setId(id) .setSampleMimeType(mimeType) .setAverageBitrate(bitrate) .build() val newFormat = format.buildUpon() .setMaxInputSize(maxSize).build()

TrackGroupArray → Tracks API
2.18 → M3 1.5 Rewrite 3–5 files
TrackGroupArray was deprecated in 2.18 and fully removed in M3 1.5. The replacement Tracks API represents a fundamentally different data model. This is not a rename — it requires rethinking iteration, selection, and overrides.
High Impact: Full Rewrite Required CacheBasedTrackSelector and CacheBasedAdaptiveTrackSelection require complete rewrites. The entire track selection contract — method signatures, iteration logic, and override mechanisms — has changed.
Before — Old TrackSelector contract
override fun selectTracks( rendererCapabilities: Array<RendererCapabilities>, trackGroups: TrackGroupArray, // removed periodId: MediaSource.MediaPeriodId, timeline: Timeline ): TrackSelectorResult { // Iterate: for (i in 0 until trackGroups.length) // Access: trackGroups[i].getFormat(j) }
After — New Tracks API
// Tracks replaces TrackGroupArray // Iterate via: tracks.getGroups() // Access TrackGroup: group.getMediaTrackGroup() // Apply selection: TrackSelectionOverride val groups: List<Tracks.Group> = tracks.getGroups() for (group in groups) { val mediaGroup = group.getMediaTrackGroup() // check group.isTrackSupported(index) }

Renderer Changes
2.19–M3 1.4 Adaptation ~10 files
Three breaking changes to the Renderer interface spanning 2.19 to M3 1.4. The Buffer.isDecodeOnly() removal is the most subtle — it requires a behavioral workaround.
1
2.19: release() → release(MessageQueue) — message queue now passed for async teardown coordination
2
M3 1.0: onStreamChanged(formats, startPositionUs) → onStreamChanged(formats, startPositionUs, offsetUs, MediaPeriodId) — offset and period context added
3
M3 1.4: Buffer.isDecodeOnly() removed — replace with: check getLastResetPositionUs() and compare against the buffer's presentation timestamp to determine whether to skip decode
