The daily validation loop is expensive

build → run → trigger flow → read logs → verify → fix → repeat
5–10 min per build/run cycle
20–40 min full validation pass
1+ hr/day per engineer on repeated validation
  • AI accelerates dev velocity — testing becomes the bottleneck
  • Manual validation doesn't scale with feature complexity and shipping frequency

What if you had an AI testing companion?

  • An AI companion that executes E2E flows on a real device autonomously
  • Validates behavior via runtime logs + UI state
  • Produces structured evidence reports
  • Experience compounds — context knowledge gets documented and reused
Think: "I changed this code — does it still work?" → let the AI verify it.

Currently implemented as a plugin for Claude Code · Architecture is AI-assistant agnostic

What's the magic?

⚙
Pre-recorded context knowledge
  • Snapchat-specific UI element name tags and accessibility identifiers
  • View hierarchy patterns — how screens are structured
  • Navigation knowledge — how to reach Spotlight, Stories, Chat, Camera, etc.
  • Log pattern dictionaries — what "working" looks like for each code path
  • Known edge cases — overlays, loading states, permission dialogs
  • UI dumps pre-linked with codebase — improves interpretation success rate
  • Log capture with timestamps — evidence-based validation reduces hallucination
☰
Team-owned context packs
  • Each team maintains their own context pack
  • Defines: how to trigger their flows, what signals to check, expected UI states
  • Teams extend coverage without touching the core system
  • Onboarding a new flow = add a context pack, not write automation code
  • Compounds over time — every validated run improves the pack
UI dumps + codebase linking = accurate interpretation. Log evidence with timestamps = no hallucination. Context packs = what to look for.

PR Validation → Evidence Report

From one command to a complete validation report

  • Analyzed PR diff → understood what changed
  • Derived golden rules → "what does working mean?"
  • Injected validation logs → built (fixed a build error along the way)
  • Executed on device → captured logs → validated all rules
  • Cleaned up everything → reverted logs, reset flags, restored branch
  • Generated report → verdict, timing analysis, evidence
